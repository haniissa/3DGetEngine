  (wrong `usage`, wrong `vkGetBufferMemoryRequirements` source, wrong memory/mapped
  handles). Partially corrected; a full index-buffer growth block was added.
- `Renderer.cpp` was missing `#include <imgui_impl_vulkan.h>` — `ImGui_ImplVulkan_RenderDrawData`
  is declared in the backend header, not in `<imgui.h>`.
- Depth resources (`CreateDepthResources` / `DestroyDepthResources`) were declared in
  `Renderer.h` and called in `RecreateSwapchainInternal` but never defined → linker
  "undefined reference". User typed the implementations in themselves.

### Still broken / next blockers (as of end of session)
1. `Renderer.cpp` ~line 52: `PFN_vkGetPhysicalDeviceFormatProperties(...)` used as a
   call → GCC "expression list treated as compound expression in functional cast".
   Must be `vkGetPhysicalDeviceFormatProperties(...)`. (`PFN_` = function *pointer type*.)
2. `CreateRenderPass()` ~line 367: `renderPassInfo.attachmentCount = 1;` must be `2`
   (depth attachment added but count not updated). The earlier assignment at ~line 356
   is dead code.
3. `Initialize()` never calls `CreateDepthResources()` → `m_depthImageView` is
   `VK_NULL_HANDLE` when `CreateFramebuffers()` (which now uses `attachmentCount = 2`)
   runs. Add `if(!CreateDepthResources()) return false;` after `CreateRenderPass()`.
4. `CreateGraphicsPipeline()` is still a stub that `return false;` → `Initialize()`
   aborts at that check. Nothing renders until a real pipeline is built.
5. `Shutdown()` never calls `DestroyDepthResources()` (leak), and ~line 180 frees
   `m_indexBufferMemory` inside the *uniform buffer* loop (should be
   `m_uniformBuffersMemory[i]`) → double free + leaks.
6. `FindSupportedFormat` dropped the `== features` comparison; should be
   `(props.linearTilingFeatures & features) == features`.
7. Graphics pipeline will also need `VkPipelineDepthStencilStateCreateInfo` with
   `depthTestEnable = VK_TRUE` once it's real.
