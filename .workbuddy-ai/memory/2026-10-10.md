### Current failure (runtime, caught by the validation layer)
```
VUID-VkRenderPassCreateInfo-attachment-00834
vkCreateRenderPass(): pSubpasses[0].pDepthStencilAttachment->attachment is 1,
but must be less than the total number of attachments (1)
```
Cause: `src/Renderer.cpp` `CreateRenderPass()` still has
`renderPassInfo.attachmentCount = 1;` (~line 367) while `pAttachments` points at
the 2-element `attachments[] = {colorAttachment, depthAttachment}` array and
`depthAttachmentRef.attachment = 1`. Fix: set `attachmentCount = 2`.
(There is a dead duplicate assignment `attachmentCount = 1;` at ~line 356.)

### Remaining dominoes (in the order they will hit)
1. `attachmentCount = 2` in `CreateRenderPass()`.
2. `CreateGraphicsPipeline()` must stop returning `false` — needs a real pipeline
   (shader modules from the SPIR-V, vertex input from `Vertex`, UBO descriptor set
   layout, and `VkPipelineDepthStencilStateCreateInfo` with `depthTestEnable = VK_TRUE`).
3. `Initialize()` must call `CreateDepthResources()` after `CreateRenderPass()`
   and before `CreateFramebuffers()` — otherwise `m_depthImageView` is
   `VK_NULL_HANDLE` when the framebuffer (now `attachmentCount = 2`) is built.
4. `Shutdown()` still needs `DestroyDepthResources()` and has the wrong handle in
   the uniform-buffer loop (`m_indexBufferMemory` should be `m_uniformBuffersMemory[i]`).
5. `FindSupportedFormat` still needs `(features & x) == features` instead of a
   bare truthiness check.

## Session 2: screen-recording diagnosis ("nothing works")

Video: `.../ScreenSketch/.../Recordings/20261010-0640-09.3815819.mp4` (35 s).
Extracted frames with ffmpeg, cleaned up afterwards. Observed timeline:
engine renders fine at RPM 0; at RPM>1 (throttle 1%) the engine disappears and
becomes a yellow tube/blob; the blob persists after STOP; Exploded View +
Section View checked the whole time with zero visual change.

**Root cause of the blob — single shared GPU mesh buffer.**
`Renderer` owns exactly one `m_vertexBuffer` / `m_indexBuffer`, and
`UploadMesh()` memcpy's at offset 0. `App::Render()` does
`DrawMesh(engine) → UploadMesh(particles) → DrawMesh(particles)`. Both draws
execute at queue-submit time, so draw #1 reads particle vertices with ~8000
engine indices → out-of-bounds reads → garbage yellow triangles.
Fix: upload one combined mesh (engine verts + particle verts with index offset),
or give the Renderer per-slot mesh buffers.
